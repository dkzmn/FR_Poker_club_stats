# FR Poker Club — статистика турниров

Автоматический сбор результатов турниров из телеграм-канала
[t.me/FRPokerClub](https://t.me/FRPokerClub) и сайт со статистикой.

## Как это работает

```
t.me/s/FRPokerClub → scraper.py → SQLite (raw_messages)
                     parser.py  → tournaments, results
                     aggregate.py → docs/data.json
                     docs/index.html (Chart.js) — статический сайт
```

Запуск полного цикла:

```bash
pip install -r requirements.txt
python3 scraper.py      # догружает новые посты (--full — вся история заново)
python3 parser.py       # пересобирает таблицы турниров/результатов
python3 aggregate.py    # пишет docs/data.json
python3 -m http.server -d docs 8000   # локальный просмотр: http://localhost:8000
```

## Конфигурация

- `seasons.json` — границы сезонов (рейтинг обнуляется каждый сезон).
  **При старте нового сезона нужно добавить строку** — агрегатор напомнит
  предупреждением, если встретит турнир позже конца последнего сезона.
- `aliases.json` — склейка разных написаний одного игрока.
  Регистр, пробелы и ё/е выравниваются автоматически, сюда — только
  настоящие расхождения (например, `Гуру Покер` → `Гуру Покера`).

## Автоматизация

`.github/workflows/update.yml` — ежедневный запуск в GitHub Actions:
скрейпинг, пересчёт, коммит `data.json` и деплой на GitHub Pages.
В настройках репозитория включите Pages → Source: GitHub Actions.

## Особенности данных

- Ранние турниры (январь–март 2026) публиковались без очков — они входят
  в статистику побед/подиумов, но не в очковый рейтинг.
- Место игрока определяется порядком строк в посте (в bounty-турнирах
  очки не монотонны по местам).
- Финал сезона — отдельное событие: в очковый лидерборд не входит,
  победитель получает достижение «Чемпион сезона».
- Парсер пишет в stderr предупреждения о нераспознанных строках —
  так изменение формата постов не пройдёт незамеченным.
